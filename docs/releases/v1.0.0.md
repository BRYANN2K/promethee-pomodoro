# Promethee Pomodoro 1.0.0 release candidate

**Status:** Local candidate preparation. `promethee-pomodoro@1.0.0` has not been published, tagged, installed from the public registry, or promoted to npm `latest`.

## What this candidate adds

Promethee Pomodoro adds a Pomodoro cycle around the real Promethee compact timer instead of creating a second session timer. The outline consumes during focus and breaks, the local handle opens a compact menu beside the HUD, and placement fails closed when current geometry is unsafe.

The candidate includes:

- focus, short-break, long-break, and long-break cadence settings;
- French UI when the operating-system language begins with `fr`, English otherwise;
- point-in-time task selection from strict read-only `tasks` and `task_projects` queries;
- local per-task running-time tracking in `task-time-v1.json`, with task-switch/Stop-tracking closure, retained task/project snapshots, corrupt/future-file preservation, and deterministic newest-10,000/`<8 MiB` retention;
- a four-tab Context/Tasks/History/Settings menu, newest-first 100-entry pages with **Load older**, individual deletion across retained history, DST-aware local calendar aggregates, and explicit freelancer-oriented CSV export with UTC timestamps, spreadsheet-safe escaping, and no Promethee session identifier;
- non-authoritative current timer state from eight allowlisted `sessions` fields;
- macOS automatic Pause at focus completion and Resume at break completion, with new-install defaults of Pause on and Resume off;
- first-launch macOS permission onboarding with prompt-free initial refresh, followed after onboarding presentation by at most one native permission request per process when required; **Allow** remains the explicit retry, while Check again/Settings review and every phase transition are request-free. Helper-reported Input Events supplies the control check; helper Screen Recording plus a bounded non-retained `/usr/sbin/screencapture` probe supplies the reading check. The centered recovery panel can show without HUD geometry, a guarded bounded-flush relaunch follows newly detected Screen Recording, **Continue** appears after both checks pass, and final System Settings toggles remain user-controlled. **Not now** may skip Input Events and save both automation settings off only after mandatory screen reading is verified; missing Input Events alone then neither reopens recovery nor reissues the startup request on later launches;
- a local **Reset timer** action that restarts only the current Pomodoro phase and never controls or resets Promethee;
- **Skip phase**, which uses the existing bounded Pause authority for focus and moves a break locally to Ready;
- native notifications, local bounded preferences, and manual update detection;
- adaptive 16 ms-to-100 ms HUD geometry polling plus packaged SVG/ICNS application icons and a secondary local macOS Electron application installer;
- orange focus progress with a neutral gray consuming break outline; and
- the `promethee-pomodoro` npm CLI with normal, foreground, and no-launch version entry points; normal/foreground launch fails closed outside macOS arm64/x64 and Windows x64.

## Safety boundary

On a new installation, automatic Pause initially defaults to on and automatic Resume defaults to off. Verified screen reading—helper-reported Screen Recording plus the real bounded capture probe—is required for HUD attachment. Once it passes, choosing **Not now** may skip Input Events and persists both automation settings off for passive use without recovery reopening solely for missing control; while screen reading is unavailable, **Not now** is refused. Existing stored values are otherwise preserved; later enabling either setting remains explicit and user-controlled, and the environment kill switch overrides them. On macOS, an eligible action requires verified screen reading plus helper-reported Input Events, performs two fresh same-session SQLite observations and two matching bounded HUD captures, then permits at most one native click. Start, Stop, End, database writes, private IPC, credentials, broad capture, and automatic retry are absent. A later matching observation updates current state but is not command acknowledgement or proof of causation.

The local reporting ledger is separate from Promethee. It accrues only while a selected task and the real session observation are running, persists bounded task/project snapshots and local interval timestamps, and never persists or exports the Promethee session identifier. Deleting history or writing a CSV affects local files only.

## Platform evidence

The macOS bridge has one authorized live Promethee 1.3.29 same-session focus → pause → short break → resume → focus result. The running HUD measured `159 × 32`; the paused HUD measured `191 × 32`.

Windows x64 is a passive attached candidate for HUD location, allowlisted task/session observation, and manual Pomodoro transitions. Promethee Pause/Resume automation is unavailable and fails closed. No Windows package install/runtime result may be claimed until the final clean Windows matrix passes; macOS evidence never establishes Windows support.

## Distribution boundary

V1 is an npm source/runtime package, not a native `.app`, `.dmg`, `.pkg`, `.exe`, or `.msi`. It has no Promethee Pomodoro Apple Developer ID, notarization, Windows Authenticode signature, or native installer identity. Users need the documented Node/npm and platform prerequisites.

The stable npm `latest` tag requires explicit manual approval of the exact source revision, candidate tarball, integrity, package version, workflow identity, and registry target. This documentation update does not publish or approve that mutation.

## Known issues

- Platform permission and reputation prompts are expected because the project is not natively signed.
- The secondary local macOS installer uses an ad hoc signature whose `cdhash` changes across builds. It resets only Accessibility and ScreenCapture TCC entries for the current and retired bundle identifiers after installation; users must revalidate and regrant access after every V1 rebuild/install. This is a temporary local workaround, not the long-term update model. Stable permission identity requires a future Apple Developer ID signed build.
- Local ad hoc rebuilds can require permission regrant; native-helper status reported both grants (`1,1`) in the local check, but the actual Screen Recording grant/relaunch transition does not yet have post-build user-run live proof.
- Unknown Promethee schemas, multiple active sessions, ambiguous HUD windows, unsupported rendered glyphs, or stale geometry disable dependent behavior.
- The application does not automatically install updates. Installation, update, rollback, and removal remain explicit npm operations.
- Removing the global npm package does not silently delete local Pomodoro preferences.
- Removing the package also does not remove `task-time-v1.json` or CSV files exported to user-selected locations. The local ledger is bounded, not a permanent archive or certified invoice source.
- Cycle-snapshot lifecycle persistence is not wired into the Electron host.
- Electron is pinned to the authorized `43.4.1`; current source validation covers the dependency lock, while clean registry installation and Windows runtime evidence remain release gates.
- The npm name returned `E404` at the 2026-08-26 check. A separately authorized one-time granular-token/2FA bootstrap is required before the configured tokenless Trusted Publisher can handle later versions.
