# ADR-0004: Make the Promethee timer the session-control authority

> **Amendment note:** [ADR-0014](0014-compose-the-external-promethee-bridge.md) preserves Promethee as the sole user-facing session authority but replaces acknowledgement assumptions for the accepted external profile. An OS action remains `sent-unconfirmed`; a later fresh same-session observation may drive current Pomodoro state, but never proves causation or authorizes automatic retry. Dependent transitions wait for compatible current observed state or remain suspended.

## Context and problem

Promethee already presents the user's session play, pause, stop, and state controls. Adding a second set of Pomodoro controls would create competing sources of truth, allow visually contradictory states, and make it unclear which action owns a session transition. The requested interaction is that the real Promethee pause/play control also controls Pomodoro focus behavior: focus completion pauses Promethee for a timed break, and an early Promethee play starts a fresh configured focus.

We need explicit authority and reconciliation rules for user actions, Pomodoro deadlines, bridge acknowledgements, and duplicate or late events.

## Scope and non-goals

This decision governs session play, pause, resume, and stop coordination. It does not make Promethee authoritative for Pomodoro durations, cycle count, break deadlines, ready state, or local settings. It does not authorize automation without an approved adapter and bridge.

## Decision drivers

- Present one visible play/pause authority to the user.
- Never show a Pomodoro state that assumes an unacknowledged Promethee command succeeded.
- Preserve intentional manual pause, early resume, and stop behavior.
- Make duplicate, reordered, timed-out, and reconnect events safe.
- Keep break time independent while the Promethee session is paused.

## Constraints

- Promethee session state observed through the approved adapter is authoritative.
- Session commands require acknowledgements and reconciliation with a subsequent state snapshot/event.
- The Pomodoro menu and overlay must not add duplicate play/pause controls.
- A focus deadline cannot start a break until the requested Promethee pause is acknowledged or reconciled as already paused.
- Stop cancels the active Pomodoro cycle; it is not interpreted as an ordinary pause.

## Considered options

1. Use Promethee controls as the sole session authority and coordinate Pomodoro around acknowledged state.
2. Give Promethee and Pomodoro independent play/pause controls with bidirectional mirroring.
3. Make Pomodoro authoritative and drive Promethee as a follower.
4. Do not coordinate controls; display an independent timer as the status quo fallback.

## Decision

We will **treat the real Promethee timer as the sole user-facing authority for session play, pause, resume, and stop**. A coordinator will consume authoritative adapter events, send idempotent commands generated by Pomodoro transitions, await acknowledgements, and reconcile against fresh Promethee state after timeouts or reconnects.

During focus, a manual Promethee pause pauses Pomodoro focus. At focus completion, the coordinator requests Promethee pause and starts break only after acknowledged or reconciled pause. Break time continues while Promethee remains paused. Promethee play during break or ready cancels the remainder of that phase and starts a new full configured focus. Promethee stop cancels the Pomodoro cycle. Duplicate controls will not appear in Pomodoro UI.

## Rationale

The user already understands Promethee's timer as the session controller, and its state is the only reliable basis for Promethee work tracking. Acknowledged coordination prevents the Pomodoro from inventing a pause or resume that did not occur. Dual controls increase race paths and visual ambiguity. Making Pomodoro authoritative would subordinate the host product to an integration and risks resuming a session against the user's intent. An independent timer avoids races but fails the core automation requirement.

## Option comparison

| Driver | Promethee authority | Dual mirrored controls | Pomodoro authority | Independent timers | Evidence |
|---|---|---|---|---|---|
| Single user control | Yes | No | Pomodoro replaces expected control | Separate controls | Accepted product interaction |
| State truth | Promethee snapshot/events | Two mutable sources | Pomodoro may diverge from Promethee | Deliberately unrelated | Bridge contract requirement |
| Race surface | Bounded coordinator | Largest | Command failures still diverge | Lowest but no automation | Design analysis |
| Early play behavior | Native Promethee action starts focus | Either surface may win | Requires Pomodoro action | Uncoordinated | Accepted product interaction |
| Failure safety | Reconcile or stop automation | Ambiguous | Risk of unintended session action | Safe but incomplete | Security/reliability analysis |

## Consequences

### Positive

- The user sees one play/pause/stop interaction model.
- Pomodoro cannot silently claim Promethee changed state without acknowledgement.
- Manual pause, early restart, stop, timeout, and reconnect each have explicit semantics.
- Break duration remains accurate without requiring a Promethee session to run.

### Negative

- Focus-to-break transitions may wait briefly for a bridge acknowledgement.
- The coordinator needs command identifiers, deduplication, timeouts, reconciliation, and event-order tests.
- Pomodoro availability is intentionally degraded when required Promethee capabilities are unavailable.

### Neutral

- Pomodoro remains authoritative for its phase duration and cycle count, not for Promethee session facts.
- Menu actions such as skip break or restart focus may change Pomodoro phase but do not become duplicate session controls.

## Implementation and migration

1. Define a coordination state that distinguishes desired Pomodoro phase, observed Promethee state, and pending command.
2. Assign an idempotency identifier to each state-changing adapter command.
3. Encode the accepted transition matrix, including manual pause, focus deadline, acknowledged pause, early play, stop, timeout, reconnect, and duplicate event.
4. Make the UI derive from reconciled coordinator state and expose degraded/blocked status without counterfeit controls.
5. Validate a disposable session before enabling automatic coordination by default.

## Validation

- Transition tests cover every pair of Pomodoro state and relevant Promethee event, including duplicates and reordering.
- Focus completion never enters `break-running` while observed Promethee state is running.
- Early Promethee play during break or ready always creates a full configured focus duration.
- A stopped Promethee session leaves no active Pomodoro focus or break.
- Timeout and reconnect tests reconcile from `getActive` before any additional session command.
- UI inspection confirms that Pomodoro surfaces expose no duplicate play/pause control.

## Revisit triggers

- Promethee introduces native Pomodoro phases or delegates session-control authority to extensions.
- User research shows a required Pomodoro-only play/pause control that cannot be represented by Promethee.
- Bridge acknowledgements or state events cannot establish authoritative ordering.
- Promethee changes stop/pause/resume semantics in a way that invalidates the transition matrix.
