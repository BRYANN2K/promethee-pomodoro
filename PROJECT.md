# promethee-pomodoro

An Electron and TypeScript Pomodoro companion for Promethee on macOS and Windows.

## Active project contract

- Kind: `desktop`
- Runtime: `electron@43.2.0`
- Language: `typescript`
- Package manager: `npm`
- Dependency lock: `package-lock.json`
- Source roots: `src/core`, `src/promethee-adapter`, `src/session-coordinator`, `src/cycle-persistence`, `src/electron`
- Test roots: `Tests/core`, `Tests/integration`, `Tests/persistence`, `Tests/electron`
- Candidate targets: macOS 14+ arm64/x64 and passive Windows x64; platform support is not claimed until each target is exercised

`software-project.json` is the machine-readable source for this repository-owned contract. Ownership transferred from the original bootstrap contract on 2026-08-25 after explicit project-owner approval of Electron and npm. The project owner authorized final retirement of the abandoned Swift/prototype track on 2026-08-26; Electron is now the only implementation.

## Current implementation boundary

- The pure Pomodoro engine and typed adapter/session coordinator are implemented; the final frozen-source run passed 33 core and 71 integration tests.
- The version-1 persistence envelope, strict allowlisted codec, pure recovery policy, and storage port are implemented without platform I/O or coordinator wiring; the final frozen-source run passed 17 persistence tests.
- The Electron host composes the approved four-tab local UI (Context, Tasks, History, Settings), fixed read-only SQLite task/project and minimal session observations, native Promethee process/HUD discovery, an observation-driven cycle runtime, attached outline/handle/menu windows, task/settings/history IPC, notifications, a versioned bounded preference store, and ADR-0019's local per-task time ledger. Active Electron code uses no AppleScript, JXA, or semantic `AXPress` action path. macOS includes the bounded action path; Windows V1 is passive observation/attachment only.
- New installations initially default automatic Pause on and automatic Resume off. After the helper reports Screen Recording and a bounded real `/usr/sbin/screencapture` probe succeeds, choosing **Not now** may skip Input Events, persist both automation settings off, enter passive attached use, and avoid reopening permission recovery solely for missing timer control; it is refused while screen reading is unavailable. The probe image is never retained. Later enabling either remains explicit, and other stored preference values remain unchanged. On macOS, each eligible action reads SQLite directly for two fresh same-session preflight observations and performs two bounded HUD captures/classifications, with the second read/capture immediately before dispatch. Exact app/PID/HUD geometry/generation and the rendered Pause/Play glyph/layout must agree before the native helper issues one CoreGraphics click; there is no automatic retry. Windows automation is unavailable and fails closed. `PROMETHEE_POMODORO_DISABLE_AUTOMATION=1` forces automation off on every platform. Ordinary repository validation uses synthetic databases/injected executors and sends no command to a live Promethee process.
- The `node:sqlite` reader is main-process-only, opens one canonical database read-only with `query_only`, and uses fixed bounded allowlisted statements. Host wiring exists, but supported-version task/project schema, live side-effect, and Windows runtime proof remain unavailable.
- The external runtime maps later current observations to cycle state without treating them as acknowledgement or causation. The preference store atomically replaces settings and one selected-task reference; cycle-snapshot persistence/lifecycle recovery is still absent. **Skip phase** reuses the existing Pause authority for focus and moves a running break locally to Ready; it adds no Promethee operation. Separately, ADR-0019's `task-time-v1.json` ledger accrues local time only while a selected task and the real Promethee timer are observed as running. A task change closes and saves the prior interval; **Stop tracking** selects `null`, closes the current interval, and preserves history. Each interval retains a bounded task/project snapshot if the source task later disappears.
- The local ledger persists authorized interval timestamps but never a Promethee session identifier. It never writes to Promethee. It retains the newest 10,000 closed entries while keeping the encoded snapshot strictly below 8 MiB, evicting the oldest entries deterministically when necessary. History is paged newest-first at 100 entries per request with **Load older**, so every retained entry remains individually deletable. Today/week aggregates use local calendar boundaries and are DST-aware. Corrupt or future-version files fail closed and remain untouched.
- Runtime work is bounded: task refresh uses a slow cadence, active task-time state checkpoints nominally every five seconds and renders history at most once per second, geometry polling adapts from 16 ms during change/recovery to 100 ms after 750 ms of stability, and window plans are applied only when geometry changes or recovers. Runtime generation tracks host lifecycle and is distinct from HUD generation, so moving the timer updates geometry without terminating the current polling lifecycle. The packaged SVG/ICNS application icon is also used by the secondary local macOS Electron application installer.
- First launch on macOS shows a permission panel that first preflights Screen Recording and Input Events independently. The permission/onboarding and missing-geometry recovery menu is centered in the current display without depending on HUD geometry. **Check again** is also preflight-only. After the startup refresh and onboarding presentation, the host may invoke the native permission request automatically at most once per process when a required capability is missing; macOS may show the Accessibility prompt/register the app, while the user remains sole authority for final System Settings toggles. No phase transition requests permission. The timer-control row reflects native-helper Input Events status. The screen-reading row and attachment authority require both helper-reported Screen Recording and a bounded probe through the real `/usr/sbin/screencapture`; no probe image is retained. The primary button says **Allow** while either check is missing and remains an explicit request retry. If Screen Recording changes from false to true during a request, one guarded relaunch revokes automation authority, aborts native control, stops poll rescheduling, waits at most 750 ms for queued preference and local task-time checkpoints, then invokes `app.relaunch()` and `app.exit(0)`; after both checks pass, the button is **Continue**. Ordinary quit uses the same bounded checkpoint-and-`app.exit(0)` path without relaunch. Open links to the relevant System Settings pane, but the user remains the sole authority for the final OS toggles. Screen reading is mandatory for HUD attachment. Once it passes, **Not now** may skip Input Events, complete onboarding in passive mode, atomically persist automatic Pause and Resume as off, and suppress future recovery/request solely for the absent optional control permission; while screen reading is unavailable, **Not now** returns permission-required and setup remains open. **Settings → Permissions → Review** reopens the panel and passively rechecks both capabilities, and enabling automation later remains explicit. Denial or revocation keeps automation fail-closed, so a phase transition never becomes a permission prompt. Local ad hoc rebuilds may require regranting access. Reopening the single-instance application brings the existing popup forward, using centered recovery or attached placement as current state allows, instead of silently returning while the Dock icon is hidden.
- On 2026-08-25, one separately authorized macOS exercise against Promethee 1.3.29 passed a full same-session focus → pause → short break → resume → focus flow. The observed HUD was `159 × 32` while running and `191 × 32` while paused. This narrow result is not acknowledgement/causation, Windows, a supported-version matrix, installation, or release proof.
- The active host still lacks a supported HUD-exclusion feed, post-build live Screen-Recording-grant-and-automatic-relaunch/denial/revocation/regrant proof for the implemented permission lifecycle, Windows runtime proof, and proven platform z-order/input behavior. A local 2026-08-26 helper check reported both permission flags granted (`1,1`), and a separate lifecycle smoke confirmed that a second launch reopened the popup and a `TERM` quit followed by manual reopen passed; neither exercised the OS grant/relaunch transition. Local ad hoc signatures have a changing `cdhash`, so `install-electron.sh` resets only Accessibility and ScreenCapture TCC rows for the current and retired bundle IDs after installation; it never grants access and the user must revalidate/regrant after every V1 rebuild/install. This is a temporary workaround, not a durable update identity. Future Apple Developer ID signed delivery is the stable solution. **Reset timer** restarts only the current local Pomodoro phase at its configured duration and never controls or resets Promethee. Break progress uses the neutral gray outline token rather than the focus orange.
- Promethee remains the sole authority for session controls. The target integration may request only the explicitly negotiated operations described by the bridge contract.
- V1 is configured as the public unscoped npm package `promethee-pomodoro@1.0.1`, with a CLI and prebuilt-helper targets for `darwin-arm64`, `darwin-x64`, and passive `win32-x64`. The stable workflow assembles one reviewed tarball, verifies clean installation and Electron readiness on all three targets, publishes npm through OIDC, then creates the GitHub Release. The immutable `v1.0.0` candidate run built all helpers but exposed macOS install-root and Windows stdout-smoke defects before publication; its tag remains historical and no package or GitHub Release was created. The npm name returned `E404` on 2026-08-26, so V1 first needs the separately authorized granular-token/2FA bootstrap, registry readback, token revocation, and exact Trusted Publisher setup. The `latest` mutation requires explicit manual approval. The checked-in macOS source installer remains a secondary path.
- The approved dependency lock pins Electron `43.2.0`. Current source validation covers the TypeScript application and local helper build, but does not turn the running app into a different runtime or establish Windows support.
- Publication, installation support, and macOS/Windows compatibility are not established by a local build.

## Constraints

- Keep deterministic Pomodoro behavior independent from Electron and Promethee transport details.
- Keep every Promethee interaction behind the typed, versioned adapter. ADR-0014 accepts the external bridge composed from ADR-0011/ADR-0012/ADR-0013.
- Read-only row access is limited to `tasks`, `task_projects`, and ADR-0013's eight minimal `sessions` fields. Every write, arbitrary table/content read, credential/token/cookie access, private IPC call, and raw content diagnostic remains prohibited.
- ADR-0019 permits a separate local reporting ledger containing selected task/project snapshots and locally derived interval timestamps. Promethee session identifiers remain ephemeral and must not be persisted, sent to the renderer, logged, or exported. Local history deletion and CSV export never mutate Promethee.
- Native OS-mediated actions are limited to exact Pause/Resume for the same session on macOS, permissioned through native-helper Input Events status plus verified screen-reading capability, strongly identified, visually preconditioned, fresh, serialized, and never automatically retried. Initial new-install defaults are Pause on and Resume off; after screen reading is verified, choosing **Not now** may skip Input Events and persists both off, later enabling either remains explicit, other persisted choices remain unchanged, and the environment kill switch always wins. A click is eligible only after both action capabilities plus two direct SQLite preflight reads and two bounded HUD captures/classifications agree on the same session, app/PID, HUD geometry/generation, and exact rendered Pause/Play layout; the second read/capture occurs immediately before the single dispatch. Windows automation and Start, Stop, and End are absent.
- Fail closed when protocol, grants, geometry, exclusions, revisions, or platform behavior are unknown.
- Keep the real Promethee timer visible and interactive; local outline failure must never intercept its controls or transient `Accept` surface.
- Select French when the primary operating-system language begins with `fr`; select English for every other language until an explicit preference is implemented.
- Preserve privacy: no telemetry and no Promethee content in update checks.
- Do not claim a package is installable, published, signed, or platform-supported before the corresponding artifact and runtime evidence exist.

## Active validation contract

The repository declares these local checks:

- `typecheck`: `npm run target:typecheck`
- `test-core`: `npm run target:test:core`
- `test-integration`: `npm run target:test:integration`
- `test-persistence`: `npm run target:test:persistence`
- `test-electron-synthetic`: `npm run target:test:electron`
- `build`: `npm run target:build`
- `verify-release-package`: `npm run target:verify-release`

These commands are declarations, not evidence that a particular revision passed. Inspect each command and its side effects before execution. `target:typecheck` runs the TypeScript build graph and may refresh generated output; `target:build` writes generated output under `dist/`; `target:verify-release` reads built outputs and performs a bounded `npm pack --dry-run --json --ignore-scripts`. `target:start` builds and launches the live attached integration, so it may open the allowlisted Promethee database, invoke the native process/window helper, preflight input-event permission, run the bounded non-retained `/usr/sbin/screencapture` readiness probe, create local windows, and—after startup preflight plus onboarding presentation—invoke the native permission request once per process if required. It is an interactive product exercise, not a validation command. **Allow** can explicitly retry the request; no phase transition requests permission. Initial new-install defaults are automatic Pause on and automatic Resume off. Verified screen reading is required for HUD attachment; only after it is present may **Not now** skip Input Events, persist both automation settings off, and enter passive attached use without permission recovery/request reopening solely for missing control. Windows automation is unavailable, and the environment kill switch forces automation off.
